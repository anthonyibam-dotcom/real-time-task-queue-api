### 2. Core Functional Requirements

1. **Async Job Triggers (REST Endpoints)**:
   - `POST /api/v1/tasks/bulk-import`: Accepts a CSV file upload containing student grade records. Offloads processing to a Celery worker. Returns a unique `task_id`.
   - `POST /api/v1/tasks/generate-report`: Triggers asynchronous generation of a student performance report (PDF/CSV format). Returns `task_id`.
   - `GET /api/v1/tasks/{task_id}`: Standard REST endpoint returning current state (`PENDING`, `STARTED`, `PROGRESS`, `SUCCESS`, `FAILURE`) and percentage completion.

2. **Real-Time WebSocket Progress Updates (`/ws/tasks/{task_id}`)**:
   - Establish a WebSocket endpoint allowing clients to subscribe to a specific `task_id`.
   - Use Redis Pub/Sub or Celery state hooks to stream live JSON updates as the task processes:
     `{"task_id": "...", "status": "PROGRESS", "progress": 65, "message": "Processing row 650 of 1000"}`
   - Cleanly close the WebSocket connection once the task completes (`SUCCESS`) or errors out (`FAILURE`).

3. **Celery Worker Configuration**:
   - Configure Celery with Redis as both message broker and result backend.
   - Implement custom task states and progress callbacks that update Redis state during chunked row processing.

4. **Docker & Orchestration Setup**:
   - Include a complete `docker-compose.yml` that provisions:
     1. `web`: FastAPI application server.
     2. `celery_worker`: Background process running tasks.
     3. `redis`: Broker and cache layer.
